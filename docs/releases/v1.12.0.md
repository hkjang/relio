## Relio v1.12.0 — 조직 계정으로 MCP 연결, 오류 없는 MCP 응답, SSO 우선 로그인

이번 릴리스는 세 가지를 다룹니다. MCP 에이전트가 개인 키 없이 Keycloak 조직 계정으로 로그인할 수 있게 했고, MCP 응답에서 클라이언트를 멈추게 하던 오류 소지를 전수 점검해 없앴으며, 로그인 화면을 조직 계정 중심으로 바꿨습니다. 모든 항목을 실제 Keycloak 26.4, Qwen Code 0.20.1, OpenCode 1.17.13, 공식 MCP SDK로 검증했습니다.

## 1. 조직 계정(OAuth)으로 MCP 연결

지금까지 MCP는 개인 연동 키로만 연결할 수 있었습니다. 이제 관리자가 켜면 MCP Authorization 명세에 따라 Relio가 **OAuth Resource Server**로 동작합니다.

- 토큰 없이 접속한 클라이언트에 `401`과 `WWW-Authenticate: Bearer … resource_metadata="…/.well-known/oauth-protected-resource/mcp"`를 돌려줍니다.
- Protected Resource Metadata(RFC 9728)가 Keycloak을 Authorization Server로 알려 줍니다.
- 클라이언트가 PKCE(S256)와 `resource`(RFC 8707)로 Keycloak 로그인을 띄우고, 발급된 Access Token으로 MCP를 사용합니다.

Relio가 받는 토큰의 조건: Keycloak 서명, Issuer, 유효기간(`exp`/`nbf`), ID·Refresh 토큰이 아닐 것, `aud`에 Relio(리소스 URL 또는 SSO Client ID), 필수 Scope(설정 시). 거부 사유는 RFC 6750 형식(`invalid_token`, `403 insufficient_scope`)으로 알려 클라이언트가 다시 로그인하게 합니다.

**기본값은 꺼짐**입니다. 에이전트가 로그인한 사용자의 Role 권한 전체로 동작하기 때문입니다. 켜기 전의 동작은 그대로이며, REST API가 기존에 받던 Bearer 토큰 규칙도 바뀌지 않습니다.

### 관리자 화면

**연동 키 · API · MCP → 조직 계정(OAuth)으로 MCP 연결**

- OAuth 허용, 필수 Scope, 에이전트용 Public Client ID 설정
- 리소스 URL·메타데이터 URL·Authorization Server 표시
- 준비 상태 점검(`GET /api/v1/admin/mcp/oauth`): SSO, 서비스 URL, Keycloak 메타데이터, 동적 등록, Audience, Scope
- Keycloak 설정 순서 안내

### 사용자 화면

**개인 연동 키 → MCP 사용 안내**에 `개인 연동 키 / 조직 계정(OAuth)` 전환이 생겼습니다. OAuth를 고르면 Qwen Code와 OpenCode 설정이 서비스 URL과 Client ID가 채워진 상태로 나옵니다.

### 실측으로 찾아 반영한 Keycloak 조건

| 증상 | 원인 | 조치 |
|---|---|---|
| 동적 등록이 `Allowed Client Scopes`로 거부 | 클라이언트가 광고된 Scope를 등록 요청에 옮겨 적는데, Keycloak은 `openid`가 들어가면 거부 | Relio는 `openid`를 광고하지 않음(Access Token에 불필요) |
| OpenCode 동적 등록이 `Trusted Hosts`로 거부 | OpenCode가 `client_uri: https://opencode.ai`를 보냄 | Trusted Hosts에 `opencode.ai` 추가 안내(문자열 비교, 외부 통신 없음) |
| Qwen Code 동적 등록 실패 | Qwen이 Issuer 경로(`/realms/…`)를 버리고 호스트 루트에서 메타데이터를 찾음(0.20.1 실측, 0.24.4 동일 코드) | Qwen은 Public Client ID 사용 안내 |
| 모든 요청이 `invalid_token` | Keycloak Access Token의 `aud`에는 기본으로 `account`만 있음 | Client Scope에 Audience Mapper 설정 안내 |

### 운영

- Keycloak 서명 키와 메타데이터를 캐시합니다(15분, 모르는 `kid`는 30초에 한 번까지 갱신, Keycloak 장애 시 6시간 동안 기존 키로 검증). 이전에는 Bearer 요청마다 Keycloak을 두 번 호출했습니다.
- `mcp_request_logs`에 `auth_method`와 `oauth_client`(Keycloak `azp`)를 기록합니다.
- 처음 MCP로 들어온 SSO 사용자는 브라우저 첫 로그인과 같은 규칙(자동 생성 설정, 기본 Role)으로 만들어집니다.

## 2. MCP 응답 오류 소지 전수 점검

조회 도구 50개를 공식 MCP SDK로 150번(빈 인자, 정상 인자, 잘못된 인자) 호출해 실제로 깨지는 곳을 찾았습니다.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| SDK 기반 클라이언트에서 실패 | **24개 도구 · 70회 호출** — 목록을 `structuredContent`에 배열로 반환해 스키마 검증 실패 | 0회 |
| DB 오류 원문 노출 | 16개 도구 — `invalid input syntax for type uuid … (SQLSTATE 22P02)` | 0회 |
| 표기만 다른 필터(`customer_id`) | 조용히 무시하고 **다른 고객의 기록까지 반환** | `customerId`로 맞춰 적용 |
| 숫자 문자열 `"5"` | 기본값으로 대체 | 숫자로 변환 |

### 수정 내용

- `structuredContent`는 항상 객체로 반환합니다. 목록은 `{ "items": [...], "count": n }`이고, `content[0].text`는 이전과 같은 JSON이라 텍스트를 읽는 클라이언트에는 변화가 없습니다.
- 도구 인자를 실행 전에 각 도구의 `inputSchema`로 검사합니다. 필수 누락, UUID가 아닌 ID(찾을 검색 도구를 함께 안내), 알 수 없는 인자, 잘못된 형식을 `isError` 결과로 돌려 모델이 스스로 고치게 합니다(2025-11-25 명세 권고). 잘못된 쓰기 호출 54건이 모두 실행 전에 거부되는 것을 확인했습니다.
- DB 오류는 SQLSTATE별 안내 문장으로 바꾸고, 원문은 요청 ID와 함께 서버 로그에만 남깁니다.
- JSON-RPC 형식을 바로잡았습니다.
  - 파싱 오류에 `"id": null`
  - 지원하지 않는 `MCP-Protocol-Version`에 HTTP `400`
  - `result`와 `error`가 모두 없는 응답 제거
- 도구 하나의 내부 오류(panic)가 그 요청에만 오류로 남고, 배치의 다른 응답은 정상으로 돌아갑니다.
- SDK가 세션마다 보내는 `GET /mcp` 확인 요청(405)을 실패로 기록하지 않습니다.
- `resources/read`의 없는 리소스는 명세 코드 `-32002`로 응답합니다.

## 3. 로그인 화면 — 조직 계정 우선

- SSO가 켜져 있으면 **조직 계정으로 SSO 로그인**이 주 버튼입니다. 관리자 계정은 **관리자 계정으로 로그인**을 펼쳐야 보이는 복구용 경로로 옮겼습니다. AppStore 로그인 화면과 같은 구조입니다.
- 자동 로그인(silent SSO)이 Keycloak 세션이 없어 거절되면 "조직 계정 세션이 없어 자동으로 로그인하지 않았습니다"라고 알려 줍니다. 이전에는 이유 없이 로그인 화면만 보였습니다.
- SSO가 없는 설치에서는 이전처럼 관리자 입력란이 바로 보입니다.

자동 로그인 자체는 v1.11 계열에 이미 구현되어 있었습니다. 실제 Keycloak에서 다시 확인했습니다.

- 세션이 없으면 `prompt=none` 시도 1회 후 로그인 화면
- 새로고침해도 재시도 안 함
- 세션이 있으면 깊은 링크로 바로 진입
- 로그아웃 후에는 다시 자동 로그인하지 않음

## 업그레이드

`015_mcp_oauth.sql`이 설정 세 개(`mcp.oauth_enabled=false`, `mcp.oauth_required_scope`, `mcp.oauth_client_id`)와 `mcp_request_logs` 열 두 개를 추가합니다. 기존 개인 키, SSO, MCP 동작은 바뀌지 않습니다.

MCP 결과를 텍스트가 아니라 `structuredContent`로 읽는 자체 스크립트가 있다면, 목록 도구의 값이 배열에서 `{items, count}`로 바뀐 점을 반영하세요. 이전 배열 형태는 공식 SDK 기반 클라이언트에서 오류였습니다.
