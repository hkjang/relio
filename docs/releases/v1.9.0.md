## Relio v1.9.0 — 방문자 분석과 CSP, 그리고 AI가 다루는 고객 요청

Relio v1.9.0은 두 가지를 추가합니다. 사내 방문자 분석을 보안 정책을 직접 수정하지 않고 연결하는 체계, 그리고 MCP를 통해 AI 에이전트가 고객 요청까지 처리하는 도구입니다.

## 1. 방문자 분석 (GA · Matomo · Plausible · Umami · 직접 지정)

### 보고된 문제

추적 스크립트를 넣으면 브라우저가 이렇게 막습니다.

```
Connecting to 'https://momento.…/collect/v1/events' violates the following
Content Security Policy directive: "connect-src 'self' ws: wss:"
```

정책이 제 역할을 한 것입니다. 소스에서 헤더를 직접 고치면 그 배포 하나는 해결되지만 다른 모든 배포의 정책이 조용히 넓어집니다.

### 해결 방식 — 정책을 설정에서 도출

관리자가 공급자를 등록하면 **입력한 출처만** `script-src`, `connect-src`, `img-src`에 추가됩니다. 기본 상태에서는 아무것도 활성화되지 않으므로 무설정 빌드는 여전히 외부 요청을 하지 않습니다.

| 상태 | connect-src |
| --- | --- |
| 기본 | `'self'` |
| 사내 수집기 활성화 | `'self' https://momento.example.com` |

정책은 요청 시점에 조립하며 30초 캐시와 변경 즉시 무효화를 사용합니다. 공급자를 삭제하면 다음 응답부터 정책이 다시 좁아집니다.

### 관리자 권한이 스크립트 실행 권한이 되지 않도록

추적 스크립트는 관리자가 붙여넣은 JavaScript가 아니라 **검증된 필드로 서버가 생성**해 `/analytics.js`에서 제공합니다. `script-src 'self'`가 로더를 그대로 포함하므로 벤더 호스트만 정책에 추가하면 됩니다.

이것이 중요한 이유: 임의 스크립트 붙여넣기를 허용하면 `admin:write` 권한이 곧 모든 사용자 세션에 대한 영구 코드 실행 권한이 됩니다.

입력값은 이스케이프가 아니라 **좁은 형태 검증**으로 다룹니다. 헤더에 들어가는 값에서는 공백 하나나 세미콜론 하나가 정책 전체를 다시 쓸 수 있기 때문입니다.

- 출처는 스킴 + 호스트(+포트)만 허용. 경로·질의·자격증명·정책 분리 문자 거부
- 하위 도메인 와일드카드는 선행 `*.` 한 번만, 스크립트 출처에는 불가
- 스크립트 경로에 `//`와 `..` 거부 (출처 이탈 방지)
- 사이트 ID는 문자열 리터럴을 끝낼 수 없는 문자만 허용하고 생성 시 재이스케이프
- 태그 속성은 `data-*`만 허용. `src`, `onerror` 거부

`analytics:manage` 권한이 필요하며 일반 관리자 권한과 분리됩니다. 모든 변경은 허용 출처 목록과 함께 감사 로그에 남습니다.

### 차단된 요청을 운영 화면에서 진단

브라우저 위반 보고를 수집해 전체 URL을 출처로 축약하고 `(directive, origin)` 단위로 집계합니다. 관리자 화면에서 차단된 출처와 발생 횟수를 보고, 유효한 출처면 **한 번의 클릭으로 허용**할 수 있습니다. 사용자 콘솔에만 남던 오류가 원인과 조치로 이어집니다.

보고 본문은 신뢰하지 않습니다. 크기를 제한하고 값을 재검증하며 유니크 제약으로 집계하므로 임의 클라이언트가 표를 키울 수 없습니다.

### 개인정보 옵션

- **Do Not Track 존중**: 브라우저가 DNT를 보내면 추적하지 않음 (기본 켜짐)
- **로그인 후에만 추적**: 로그인 화면은 제외

## 2. MCP — 고객 요청까지

VOC는 화면과 REST에서만 접근할 수 있었습니다. 에이전트가 파이프라인은 분석하면서 같은 고객의 미응답 불만은 보지 못했습니다.

도구 10개를 추가했습니다.

| 도구 | 권한 |
| --- | --- |
| `list_customer_voices` · `get_customer_voice` · `get_voice_summary` | `voice:read` |
| `get_overdue_voices` · `get_voice_categories` | `voice:read` |
| `get_customer_churn_risk` · `get_top_churn_risks` | `voice:read` |
| `file_customer_voice` · `record_voice_response` · `progress_customer_voice` | `voice:write` |

각 도구는 REST 엔드포인트와 **같은 권한**을 요구하므로 MCP로 노출해도 새로 열리는 것이 없습니다. 쓰기 도구는 같은 서비스를 거치므로 상태 전이 규칙과 해결 내용 필수 조건이 에이전트에도 그대로 적용됩니다.

## 발견 및 수정한 오류

- 추적 스크립트의 수집 요청이 `connect-src 'self'`에 막혀 동작하지 않던 문제
- 차단 원인이 각 사용자 콘솔에만 남아 운영자가 알 수 없던 문제
- 브라우저 보고가 전체 URL을 보내 출처 단위 허용이 불가능했던 문제
- VOC가 MCP에 노출되지 않아 에이전트가 계약 이후 접점을 다룰 수 없던 문제

## 검증 범위

- Go Test/Vet/`gofmt`, TypeScript Typecheck, React Production Build
- 출처·경로·사이트 ID·속성 검증 단위 테스트: 정책 분리 문자, 개행, 따옴표, 와일드카드 남용, 프로토콜 상대 경로, 경로 이탈, `onerror` 속성 등 거부 확인
- CSP 조립 단위 테스트: 비활성 공급자 제외, 스크립트 출처의 connect-src 자동 허용, 별도 수집 호스트, GA4 픽셀 출처, 무설정 시 빈 정책, 헤더 결합 안전성
- 실제 브라우저 검증: 다른 출처의 추적 스크립트 로드 → 수집 엔드포인트 fetch 성공 → CSP 콘솔 오류 0건 → 공급자 삭제 시 정책 즉시 축소
- 오프라인 자산 검사에 벤더 호스트 하드코딩 금지 규칙 추가. 실제로 GA 스크립트를 심어 검사가 실패하는지 역검증

## 업그레이드

마이그레이션 010이 자동 적용됩니다. **기존 동작은 바뀌지 않습니다** — 방문자 분석은 기본 비활성이며, 활성화하지 않으면 정책도 기존과 동일합니다.

소스에서 CSP 헤더를 직접 수정해 사용하던 배포는, 그 수정을 되돌리고 `/admin/analytics` 화면에서 출처를 등록하는 방식으로 옮기는 것을 권장합니다. 그래야 허용 범위가 감사 기록에 남고 배포마다 흩어지지 않습니다.
