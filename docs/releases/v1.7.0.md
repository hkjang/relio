## Relio v1.7.0 — 고객의 목소리, 한국어 인터페이스, 읽히는 화면

Relio v1.7.0은 세 가지를 바꿉니다. 계약 이후의 고객 접점을 관리할 수 있게 하고, 화면 용어를 한국어 기준으로 정리하고, 깨져 보였던 레이아웃과 너무 작던 글자를 고쳤습니다.

## 1. 고객의 목소리 (VOC) — 계약 이후의 수명주기

기존 Relio는 판매까지만 다뤘습니다. 불만, 요청, 문의, 이탈 징후는 담당자 메일함에만 남아 고객을 담당하는 사람조차 볼 수 없었습니다.

### 단순 기록이 아닌 수명주기

- 접수 → 내용 확인 → 진행 → 고객 회신 대기 → 해결 → 종결. 전이 규칙은 서버가 소유합니다.
- 접수에서 종결로 건너뛸 수 없고, **해결에는 해결 내용 기록이 필수**입니다.
- 종결된 건의 재처리는 명시적 재오픈이며 조용한 수정이 아닙니다.
- 상태 변경, 고객 응대, 내부 메모, 상위 보고는 모두 append-only 이력으로 남습니다.

### SLA는 코드가 아니라 데이터

- 요청 유형마다 응답·해결 목표 시간을 관리자가 정의합니다. 심각도가 이를 추가로 단축합니다(긴급 = 응답 2시간, 해결 24시간).
- 기한은 비정규화해 저장하므로 기한 초과 조회가 단일 인덱스 스캔입니다.
- 초과 판정은 한 곳에서 계산해 목록, 고객 360 패널, 요약 지표가 항상 같은 값을 보여줍니다.
- 9개 유형을 현실적인 목표와 함께 기본 제공합니다 — 품질 불량 2시간, 기능 개선 요청 1일.

### 기록으로 끝내지 않고 닫습니다

- 해결 시 근본 원인, 재발 방지 조치, 고객 만족도(5점)를 기록합니다.
- 고객 응대를 기록하면 첫 응답 SLA가 충족 처리됩니다.

### 권한 분리

응대는 판매와 다른 업무이므로 `voice:read`, `voice:write`, 그리고 타인 담당 건 처리·재배정을 위한 `voice:manage`로 분리했습니다.

### 화면

- 전용 목록: SLA 카운트다운, 기한초과·긴급·이탈징후 원클릭 필터, CSV 내보내기
- 고객 360 패널: 담당자가 파이프라인 옆에서 계약 이후 관계를 함께 봅니다
- 관리자 화면: 요청 유형과 SLA 목표 관리
- 영업활동에서 **고객 요청으로 접수** 버튼으로 즉시 전환

## 2. 오늘 먼저 할 일 — 지표 대신 행동

Dashboard가 숫자만 나열해 "무엇부터 해야 하는지"는 사용자가 추론해야 했습니다. 실제로 일이 발생하는 모든 영역을 하나의 우선순위 큐로 합쳤습니다.

- 기한을 넘긴 고객 요청 (약속을 깬 것이 가장 우선)
- 기한이 도래한 다음 행동
- 다음 행동이 없거나 30일 이상 접점이 끊긴 영업기회
- 갱신 통지 기간에 들어왔는데 미착수인 계약
- 나에게 온 검토 요청

심각도 → 기한 순으로 정렬하며, 각 항목은 해당 화면으로 바로 이동합니다.

## 3. 이탈 위험 통합 신호

고객을 잃는 이유는 서로 다른 테이블에 흩어져 있습니다. 미해결 이탈 징후, 아무도 답하지 않은 불만, 시작하지 않은 갱신, 끊긴 접점. 하나씩 보면 넘길 만해 보입니다.

이를 하나의 0~100 점수로 합산하되 **근거를 함께 제시합니다.** 각 요인이 몇 점을 왜 받았는지 보여주고, 가장 큰 요인에 맞는 권장 행동을 제안합니다. 진행 중인 영업기회가 있는 상태의 이탈 징후는 없는 경우와 다른 조치를 안내합니다.

Dashboard에 위험 고객 순위를, 고객 360에 근거 상세를 표시합니다.

## 4. 깨진 레이아웃 수정

- **전략 고객 계획**이 스타일 없는 인라인 필드로 렌더링됐습니다. 이 폼이 `.form label`(라벨을 컨트롤 위에 쌓는 규칙)이 필요한 `form` 클래스를 선언하지 않았기 때문입니다. 영업 분석 정책 폼도 같은 결함이었습니다.
- `relationship-intelligence.css`가 정의되지 않은 `var(--border)`를 참조해 CSS 파서가 해당 `border` 선언을 통째로 버렸습니다. 관계도 캔버스, 협업팀 행, 역할 카드의 외곽선이 사라진 원인입니다. 실제 토큰인 `--line`으로 교정했습니다.
- CSS가 전혀 없던 패널(관계 분석 지표, 우선 조치, 설정 변경 비교, 프로필 정보)을 추가했습니다.
- 한국어 라벨이 코드보다 넓어 관계도의 노드와 연결선 캡션이 겹쳤습니다. 캔버스 기하를 넓혔습니다.

## 5. 글자 크기

330개 font-size 선언 중 191개가 8~10px로 한국어에 지나치게 작았습니다. 작은 쪽은 크게 올리고 큰 숫자는 거의 유지하는 단계적 스케일을 적용했습니다.

헤드리스 브라우저로 24개 화면을 감사해 11px 미만으로 렌더링되는 요소를 셌습니다: **적용 전 229개 → 적용 후 3개**(마이크로 태그).

## 6. 한국어 기준 용어

메뉴와 라벨에 영어 CRM 용어가 섞여 있었고, 상태 표시는 `REPORTS_TO`, `BEST_CASE`, `DECISION_MAKER` 같은 API 코드를 그대로 출력했습니다.

- `labels.ts` 단일 번역 사전을 도입하고 공용 `Status` 컴포넌트를 통과시켜 전 화면의 코드 표시를 한국어로 전환했습니다.
- API는 계속 안정적인 대문자 코드를 반환하며, CSS 클래스명과 `title` 속성에 코드를 보존해 색상 규칙과 연동에 영향이 없습니다.
- 내비게이션, 페이지 제목, 섹션 헤딩, 선택 목록을 번역했습니다.
- TypeScript 타입명과 겹치는 짧은 단어는 JSX 텍스트 노드 전체가 일치할 때만 교체해 코드 손상을 피했습니다.
- CSV 내보내기도 한국어 라벨로 출력합니다.

## 발견 및 수정한 오류

- 전략 고객 계획·영업 분석 정책 폼이 `form` 클래스 누락으로 스타일을 전혀 받지 못한 문제
- 정의되지 않은 `var(--border)`로 테두리 선언이 파서에서 폐기된 문제
- 아바타가 `name.slice(0,1)`로 "(주)한빛제조"를 "("로 표시한 문제
- 관계도 노드와 연결선 캡션이 겹친 문제
- 상태 표시가 사용자에게 API 코드를 그대로 노출한 문제
- CSV 내보내기가 수식으로 평가될 수 있는 고객 작성 텍스트를 그대로 내보낼 수 있던 문제

## 검증 범위

- Go Test/Vet/`gofmt`, TypeScript Typecheck, React Production Build, 환경변수·정적자산 계약
- VOC 상태 전이, SLA 계산, 기한 초과 판정, 위험도 구간, CSV 수식 차단 단위 테스트
- 실제 PostgreSQL에 001~008 마이그레이션 순차 적용 및 기본 유형·권한 시드 검증
- 실제 브라우저(Playwright)로 26개 화면 캡처 후 DOM 감사: 콘솔 오류 0, API 4xx/5xx 0, 가로 넘침 0, 11px 미만 3개
- 데이터를 실제로 노후화시켜 오늘 먼저 할 일 큐가 3개 영역(고객 요청·다음 행동·정체 영업기회)에서 채워지는지, 위험도가 새 증거에 반응하는지 확인
