## Relio v1.11.0 — 기록에서 판단으로

v1.11.0은 Relio가 무슨 일이 있었는지 저장하는 것을 넘어, **그것이 무엇을 뜻하는지** 말하게 합니다. Signal · Risk · Insight · Recommendation 네 가지 모델과 규칙 엔진을 추가했고, 추천은 실제 할 일로 전환됩니다.

함께, 오른쪽에서 열리는 상세 패널이 화면 밖으로 잘려나가던 문제를 고쳤습니다.

## 1. 우측 상세 패널이 잘려 보이던 문제

### 보고된 문제

> 고객의 목소리 상세 화면 우측 패널 뷰가 있는데 이 부분에 스크롤이 없어서 긴 경우 짤려 보이고 있어. 그리고 다른 우측 패널 뷰도 모두 마찬가지야.

### 측정한 사실

높이 760px 화면에서 패널의 실제 높이는 **1259px**이었습니다. 내용 영역은 `scrollHeight === clientHeight`, 즉 **스크롤이 발생할 수 없는 상태**였습니다. 화면 아래로 넘어간 부분에 도달할 방법이 아예 없었습니다.

### 원인 — 두 가지가 겹침

```
.drawer-backdrop { display:grid; place-items:stretch end }   /* 암시적 행이 내용 크기로 늘어남 */
.drawer-body     { overflow:auto }                            /* flex:0 1 auto + min-height:auto */
```

1. 배경의 grid 행이 `auto`라 내용만큼 커졌고, `position:fixed; inset:0`을 넘어 패널이 자랐습니다.
2. 내용 영역은 flex 항목의 기본 `min-height:auto` 때문에 **내용보다 작아지기를 거부**했습니다. `overflow:auto`는 있었지만 넘칠 일이 없으니 스크롤 막대도 생기지 않았습니다.

### 수정

행을 `minmax(0,1fr)`로 고정하고, 내용 영역에 `flex:1 1 auto; min-height:0`을 주었습니다. 머리글과 하단 버튼은 `flex:none`으로 고정됩니다.

| | 수정 전 | 수정 후 |
| --- | --- | --- |
| 패널 높이 (화면 760px) | 1259px | 760px |
| 도달 불가능하던 내용 | 1540px | 0 |
| 머리글 | 함께 밀려남 | 고정 |

덧붙여, 패널이 열려 있는 동안 **뒤 페이지의 스크롤을 잠급니다**. 겹쳐 열린 대화상자는 개수를 세어 마지막 하나가 닫힐 때 풀립니다. 긴 입력 폼은 제목이 스크롤로 사라지지 않도록 머리글을 고정했습니다.

고객의 목소리 · 영업기회 · 계약 세 화면에서 760 / 620 / 1000px 높이로 검증했습니다.

## 2. CRM Intelligence — Signal · Risk · Insight · Recommendation

```
CRM 데이터 → Signal → Risk → Recommendation → Next Action(Task)
                  ↘ Insight ↗
```

### 무엇이 저장되는가

| 모델 | 성격 | 예 |
| --- | --- | --- |
| **Signal** | 관측 | 45일간 고객 접촉 없음 |
| **Risk** | 0~100 점수로 정량화한 판단 | 관계 위험 70점 |
| **Insight** | 여러 신호를 묶은 한 문단 설명 | 부정 신호 7건이 동시에 관측됨 |
| **Recommendation** | 다음 행동과 기한 | 의사결정자를 확인하고 미팅을 잡으세요 (D+7) |

기존 Deal Health와 이탈 위험도는 **조회할 때 계산하고 잊어버리는** 값이었습니다. 그래서 아무것도 축적되지 않았고, 한 달간 조용한 고객과 어제 만난 고객은 레코드를 열어 직접 따져보기 전까지 똑같아 보였습니다.

### 구현한 규칙

| 조건 | 결과 | 심각도 |
| --- | --- | --- |
| 최종 접촉 30일 초과 | `NO_CONTACT` | 보통 · 60일 초과 시 높음 |
| Stage 체류 30일 초과 | `DEAL_STALLED` | 보통 · 60일 초과 시 높음 |
| 예상 종료일 경과 (진행 중) | `CLOSE_DATE_PASSED` | 높음 |
| 미해결 긴급 고객 요청 | `CRITICAL_VOC` | 긴급 |
| 계약 만료 D-90 이내 | `CONTRACT_EXPIRING` | D-30 높음 · D-14 미착수 긴급 |
| 담당자 없음 / 의사결정자 미지정 | `DECISION_MAKER_MISSING` | 높음 / 보통 |
| 최근 2주 접점 증가 | `ENGAGEMENT_INCREASE` | 긍정 신호 |
| 최근 견적 발행 | `QUOTE_REQUESTED` | 긍정 신호 |

Risk는 신호에 점수를 배분해 합산하고 100점에서 자릅니다. **40점 보통, 70점 높음, 90점 긴급**이며, 70점 이상에서만 추천이 생성됩니다. 아무도 실행하지 않는 조언은 패널 전체를 무시하도록 학습시키기 때문입니다.

접점이 늘고 있다는 긍정 신호는 관계 위험 점수를 **차감**합니다. 반대 증거를 무시하는 점수는 설명이 아니라 주장입니다.

### 세 가지 성질

**멱등** — 모든 레코드가 `(유형, 대상)` 기반 dedupe key를 가집니다. 두 번 실행해도 같은 행이 갱신될 뿐 쌓이지 않습니다. 실측: 두 번째 실행에서 신규 0건, 신호 수 8건 그대로.

**자가 해소** — 조건이 사라지면 신호와 위험이 닫히고 추천이 회수됩니다. 실측: 긴급 요청을 해결 처리하자 `CRITICAL_VOC` 신호와 `VOC_RISK`가 자동으로 닫히고 `RESOLVE_VOC` 추천이 사라졌습니다. 계속 쌓이기만 하는 분석은 일주일이면 소음이 됩니다.

**사람의 판단이 이깁니다** — 감수한 위험, 무시한 추천, 무시한 신호는 엔진이 되살리지 않습니다. 조건이 다시 감지되어도 마찬가지입니다.

### 점수에는 반드시 근거가 붙습니다

`근거 보기`는 점수를 만든 산술을 그대로 보여줍니다.

```
45일간 고객 접촉 없음          +35점
등록된 담당자가 없습니다        +35점
─────────────────────────────
합계 (최대 100)                70점
```

질문할 수 없는 숫자는 아무도 신뢰하지 않습니다.

### 추천 → 실제 할 일

추천을 수락하면 담당자와 기한이 있는 **Task**가 생성되어 기존 오늘 할 일 큐에 나타납니다. 무시할 때는 사유가 필수입니다. 사유 없는 무시는 시스템에 아무것도 가르치지 못하고, 반년 뒤에는 추천을 본 적조차 없는 것처럼 읽힙니다.

### 실행 방식

규칙 엔진은 **권한 없이 전체 고객을 훑고**, Data Scope는 결과를 *읽을 때* 적용됩니다. 볼 수 있는 범위가 회사가 아는 사실을 바꾸어서는 안 되기 때문입니다.

Job Runner가 15분 간격으로 실행하며(`intelligence.auto_analyze_minutes`로 조정, `auto_analyze_enabled`로 중지), 관리자는 화면에서 즉시 실행할 수 있습니다.

파생 테이블에는 `owner_id`를 두지 않았습니다. 담당자가 바뀐 뒤에도 이전 담당자에게 계속 보이는 분석이 남기 때문입니다. 가시성은 고객을 조인해 해석합니다.

### 화면

| 화면 | 내용 |
| --- | --- |
| **Customer 360** | 위험 점수, 신호, 분석, 추천 행동 |
| **영업기회 상세** | 해당 Deal로 좁힌 위험과 추천 |
| **Intelligence Center** | 담당 범위 전체의 위험·신호, 심각도 필터 |
| **내 추천 행동** | 개인 처리 큐 (대기 / 수락 / 무시) |
| **영업 현황(대시보드)** | 대기 중인 추천 상위 3건 |

### API와 MCP

REST 16개 엔드포인트를 추가했고, MCP 도구 7개(`get_customer_signals`, `get_customer_risks`, `get_deal_insights`, `get_recommendations`, `explain_risk`, `accept_recommendation`, `dismiss_recommendation`)를 노출했습니다. **REST와 완전히 같은 권한**을 요구하므로 MCP로 새로 열리는 것은 없습니다. 권한 없는 키에서는 도구 목록에 나타나지도 않는 것을 확인했습니다.

권한은 `intelligence:read` / `intelligence:write` / `intelligence:run`으로 분리했습니다. 기본 영업 Role에는 앞의 두 개가 부여됩니다. 엔진 실행은 전체 테이블을 훑으므로 관리자 권한입니다.

## 3. UI/UX 개선

- **사이드바 그룹화** — 업무 메뉴가 11개까지 늘어 훑어보기 어려웠습니다. `오늘 · 영업 · 분석 · 고객 관리`로 묶었습니다.
- **분석 결과를 하루가 시작되는 곳에** — 자기 화면에만 있는 분석은 출시 당일에만 열립니다. 대기 중인 추천을 영업 현황 화면에 올렸습니다.
- **막다른 empty state 제거** — "아직 분석이 실행되지 않았습니다"만 띄우고 실행할 방법이 없으면, 고칠 수 있는 사람에게 막다른 길입니다. 패널에서 바로 실행할 수 있습니다.
- **색만으로 전달하던 심각도에 이름을 붙임** — Intelligence Center의 위험 목록은 심각도를 점수 색으로만 표현하고 있었습니다. 색은 색각 이상 사용자에게 전달되지 않고, 읽어줄 수도 검색할 수도 없습니다. 심각도 열을 추가했습니다.

## 발견 및 수정한 오류

- 우측 상세 패널이 화면 높이를 넘어 자라고 스크롤되지 않아 내용이 잘리던 문제 (고객의 목소리 · 영업기회 · 계약 전부)
- 패널이 열린 상태에서 스크롤하면 뒤 페이지가 움직이던 문제
- 긴 입력 폼에서 제목이 스크롤로 사라지던 문제
- 생성 문구에 `NOT_STARTED` 같은 원시 코드가 그대로 노출되던 문제
- 계약 제목이 "계약"으로 끝날 때 "연간 유지보수 계약 계약 만료"로 중복되던 문제
- 조사를 추측해 "품질관리 시스템 통합이(가)"로 표기되던 문제
- Intelligence Center에서 심각도가 색으로만 구분되던 접근성 문제

## 업그레이드

마이그레이션 011이 자동 적용됩니다. 기존 데이터는 변경되지 않습니다.

첫 실행은 컨테이너 기동 후 Job Runner가 자동으로 수행하며, 즉시 확인하려면 **Intelligence Center → 지금 분석**을 누르십시오. 기본 Role(영업 담당자·영업 팀장)에는 `intelligence:read`와 `intelligence:write`가 자동 부여되고, 직접 만든 Role에는 `권한 · 데이터 범위` 화면에서 부여해야 메뉴가 나타납니다.

분석을 사용하지 않으려면 `intelligence` 네임스페이스의 `auto_analyze_enabled`를 `false`로 설정하십시오.
