## Relio v1.15.0 — 부서 민원 설정 확정 흐름과 업무 영역 고객 검색

v1.13.0에서 도입한 부서 VOC 업무 영역을 실제 운영값으로 안전하게 설정하도록 보완했습니다. 정상 동작하던 격리·SLA·지식 게이트·쓰기 도구는 유지하고, 미확정 업무 코드를 제품 예시값으로 생성하던 부분과 직접 ID 입력 시의 영역 불일치를 제거했습니다.

## 요구사항별 변경

| ID | 변경 |
|---|---|
| R-08 | 부서 전용 영역의 조직 트리 격리와 영업 지표 제외를 유지했습니다. 접수·목록·요약·이력·유사 검색에서 업무 영역 ID 접근을 서버가 먼저 검증하고, 접수 고객이 해당 영역에 등록된 고객인지도 대조합니다. 템플릿 적용 시 담당자·검토자 계정을 골라 Role을 바로 연결할 수 있습니다 |
| R-01 | `service_type`, `dev_method`, `error_code`를 접수 단계 필드로 구성합니다. 선택형은 저장 코드와 표시 명칭을 분리하고, 필수 여부·기본값을 부서 확정값으로 설정합니다. 오류코드(B124 등)는 JSON 전체 문자열 검색이 아니라 필드값 조건과 유사 사례 검색어로 검색됩니다 |
| R-02 | `resolver` 해결 주체는 정확히 4개의 확정 코드·명칭을 입력해야 템플릿을 적용할 수 있습니다. 허용 코드 외 값은 서버가 거부하며 기존 해결 내용·근본 원인·원인 근거 처리는 그대로입니다 |
| R-04 | 담당 Role에는 `voice:knowledge-review`가 없고 검토자 Role에만 있습니다. 화면도 권한이 있을 때만 판정 UI를 보이며 REST는 권한과 화면 세션을 모두 검사합니다. MCP 접수·처리·해결 도구에는 지식 상태 인자가 없습니다 |
| R-05 | 정확히 8개 유형을 코드·명칭·구분으로 입력해야 하며 모두 해당 영역의 SLA 미적용으로 생성됩니다. 다른 영역과 일반 유형의 SLA는 바뀌지 않습니다 |
| R-15 | REST `GET /api/v1/voices/workspaces/{id}/customers`와 MCP `search_workspace_customers`를 추가했습니다. 회원사명·회원사코드 검색 결과는 `customerId`, `name`, `customerCode`를 반환합니다. 동명이인은 모두 반환하고 임의 선택을 지시하는 입력은 스키마에서 거부합니다 |

## 공통 검증과 호환성

- MCP 쓰기 3종의 실행 전 담당자 미리보기·승인 안내와 write annotation을 유지했습니다. 동적 필드의 enum·default도 도구 스키마에 포함되므로 미리보기 값과 서버 저장 검증이 같은 정의를 사용합니다.
- 고객 코드 중복 범위를 **전체 고객** 또는 **업무 영역별**로 명시적으로 설정합니다. DB 복합 고유 인덱스가 동시 등록을 차단하며, 사전 검색과 등록 API 모두 명확한 중복 결과를 냅니다. 기존 설치는 종전과 같은 전체 고객 기준을 유지합니다.
- 상태 전이표와 낙관적 잠금은 그대로 적용됩니다. 사용자 정의 항목 수기 편집도 기존 상세 화면에서 가능하며, API와 동일한 필수값·허용값·담당자 권한 검사를 거칩니다.
- 같은 `service_type`·`resolver` 키를 서로 다른 업무 영역에서 독립 정의할 수 있도록 사용자 정의 항목 고유키를 영역 단위로 분리했습니다. 설정 번들은 영역 정보 없이 영역 필드를 일반 필드로 오염시키지 않도록 영역 필드를 제외합니다.
- 기존 요청·고객·유형·필드 값은 마이그레이션에서 변경하지 않습니다. 기존 고객 코드 중복 기준은 `GLOBAL`로 보존됩니다.

## 운영에서 확정해야 할 값

제품은 다음 값을 임의로 만들지 않습니다. **고객 요청 유형 · 업무 영역 → 회원사 민원 템플릿** 적용 창에 부서 확정본을 입력합니다.

- 민원 유형 8종의 코드·명칭·구분
- 해결 주체 4종의 코드·명칭
- 서비스 구분·개발방식의 코드·명칭, 세 접수 필드와 해결 주체의 필수 여부·기본값
- 회원사코드 형식과 중복 기준(전체 고객 / 업무 영역별)
- 소유 부서, 담당자 계정, 검토자 계정
- 초기 회원사코드·회원사명 목록

계정이 미확정이면 템플릿은 데이터 구조와 Role을 만들고 결과의 `pending`에 남은 계정 연결을 표시합니다. 초기 자료는 CSV 일괄 등록 또는 MCP `import_workspace_customers`로 검증할 수 있습니다.

## 검증

- Go 전체 Test·Vet·`gofmt`, TypeScript Typecheck, 프런트엔드 Test 48개, Production Build
- 완전 격리 네트워크 신규 설치: 유형 8종·필드 기본값/허용값·B124 필드 검색·SLA 미생성·상태 전이·지식 게이트·회원사 간이/일괄 등록·동명이인 검색·중복 거부를 실측
- 실제 부서 담당자·검토자·타 부서 계정으로 로그인해 담당자의 지식 판정 직접 API 거부, 검토자의 판정 성공, 타 부서의 업무 영역·민원·회원사 직접 ID 접근 거부를 실측
- MCP `tools/list`와 `search_workspace_customers`→`file_customer_voice`→`record_voice_response`→`resolve_customer_voice` JSON-RPC 호출을 실행하고 strict schema 및 저장값을 확인
- 격리 민원·회원사가 영업 Intelligence 신호에 포함되지 않음을 확인하고, SSO Secret·Personal Key의 컨테이너/볼륨 교체 후 연속성을 재검증
- 최신 공개 릴리스 v1.14.0 이미지에서 `017_mail_notifications.sql` → `018_voice_workspace_configuration.sql` 업그레이드 및 자격증명 연속성 검증

## 업그레이드

`018_voice_workspace_configuration.sql`이 선택값 표시 명칭·기본값, 업무 영역별 필드 키, 고객 코드 중복 범위를 추가합니다. 마이그레이션은 기존 데이터를 보존하며 서비스 시작 시 자동 적용됩니다.
