## Relio v1.15.1 — 주요 목록 UX 통일과 민원 편집 회귀 수정

v1.15.0의 부서 민원 기능을 재점검하고 고객·영업기회·민원·관리 목록의 탐색 방식을 통일했습니다. 기존 업무 영역 격리, 상태 전이, 지식 검토 권한과 MCP 쓰기 승인 안내는 유지합니다.

## 목록과 모바일 사용성

- 고객, 영업기회, 계약, 승인, 팀장 검토 대기, 영업 코칭, 고객 위험·신호, 민원, 사용자, 조직, 사용자 정의 항목, 상품, 업무 영역, 요청 유형, 감사 로그, 개인 연동 키의 **17개 목록**에 공통 테이블을 적용했습니다.
- 정렬 가능한 열 제목을 누르면 오름차순·내림차순·기본 순서를 전환합니다. 금액·건수·날짜는 실제 값으로, 한글 이름과 숫자가 섞인 이름은 자연순으로 정렬합니다. 빈 값은 양방향 모두 마지막이며 동률은 기존 순서를 유지합니다.
- 25·50·100건 페이지 이동, 표시 범위, 촘촘히 보기, 고정 열 머리글, 표 내부 가로 스크롤, 숫자 오른쪽 정렬을 제공합니다. 관리 목록과 민원에는 불러온 목록 내 검색도 제공합니다.
- **정렬과 페이지 이동은 불러온 데이터 안에서 적용됩니다.** 서버 조회 상한을 전체 건수처럼 표시하지 않으며, 상한에 도달하면 범위를 명시합니다. 더 넓은 데이터는 기존 서버 검색·필터로 조회합니다. CSV 내보내기의 서버 필터 동작은 그대로입니다.
- 고객 검색 초기화가 실제 조회에서도 검색어를 지우도록 수정했습니다. 행 내부 편집·즐겨찾기 버튼의 클릭이나 Enter가 행 이동까지 중복 실행하지 않습니다.
- 팀장 검토 대기·영업 코칭의 제목, 설명, 표 사이 간격을 정리했습니다. 모바일 필터 높이를 내용에 맞추고, 관리 화면의 긴 버튼이 세로로 눌리지 않도록 배치했습니다.
- 모바일은 업무·개인·관리 영역 모두 메뉴 버튼으로 전체 메뉴를 엽니다. 숨은 메뉴는 키보드 탐색에서 제외하고, 열린 메뉴의 초점 유지·Escape 닫기·원래 버튼으로 초점 복귀를 제공합니다.

## v1.15.0 민원 기능 재점검

- 접수와 해결 항목 편집을 분리했습니다. 해결 주체가 필수여도 진행 중 민원의 접수 정보 편집을 막지 않습니다. 해결 항목은 해결·종결 상태에서 편집합니다.
- 선택 항목을 비우면 서버에 명시적인 `null`을 보내 기존 값을 지웁니다. 삭제한 값을 기본값으로 다시 채우지 않으며 필수 항목 삭제는 거부합니다. 미입력 신규 항목에 설정된 기본값을 적용하는 동작은 유지합니다.
- 변경된 항목만 저장하므로 과거 저장 후 폐기된 선택 코드가 다른 항목의 편집까지 방해하지 않습니다. 다중 선택·소수 입력도 기존 필드 정의에 맞게 처리합니다.
- 상태·필드·원인 분석 편집은 담당자 또는 민원 관리자에게만 표시합니다. 기존 권한으로 허용된 처리 기록 작성과 검토자의 지식 판정은 유지합니다.
- 접수 중 업무 영역을 바꾸면 이전 고객·연락처와 입력 필드를 초기화합니다. 목록 요청의 응답 순서가 바뀌어도 최신 필터 결과만 반영하며, 조회 실패 시 재시도 버튼을 제공합니다.
- 여러 접근 가능 업무 영역이 같은 필드 키를 사용해도 MCP 스키마가 마지막 영역의 허용값으로 덮어써지지 않습니다. `anyOf`로 각 영역의 타입·허용값을 보존하고 실제 쓰기 검증은 선택한 업무 영역에서 수행합니다.

- 완전 격리 신규 설치: 부서 접근 제한·SLA·지식 게이트·회원사 검색·등록·중복 방지·MCP 접수/처리/해결 회귀 검사, 선택 항목 삭제와 필수 항목 삭제 거부

## 업그레이드와 운영 설정

추가 DB 마이그레이션은 없습니다. 기존 데이터·부서 설정·역할·키를 그대로 사용합니다. v1.15.0에서 요청한 부서 확정 코드, 필수 여부, 대상 계정, 초기 회원사 자료는 이번 UI 패치에서도 임의로 생성하거나 변경하지 않습니다. 실제 운영 서버 적용 및 운영 계정의 Qwen/OpenCode 대화 실행은 이 릴리스 검증과 별개입니다.
