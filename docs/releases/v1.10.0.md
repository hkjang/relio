## Relio v1.10.0 — 담당자를 등록하는 곳, 그리고 되돌릴 수 있는 삭제

v1.10.0은 새 기능을 얹기보다, 이미 있던 화면들이 전제하고 있었지만 실제로는 존재하지 않았던 입구를 만듭니다. 의사결정 관계도는 담당자를 고르라고 했지만 담당자를 등록할 화면이 없었고, 고객은 등록할 수만 있고 지울 수는 없었으며, 전략 고객 계획은 두 번째 칸부터 글을 쓸 수 없었습니다.

## 1. 고객 담당자 관리

### 보고된 문제

> 고객 상세에 보면 의사결정 관계도에 시작 담당자, 대상 담당자가 있는데 담당자를 입력하는 곳도 없는데 담당자를 매핑하는게 있어. 담당자 어디서 등록하는거야.

맞습니다. 어디에도 없었습니다. 담당자는 REST API로만 만들 수 있었고, 화면에서는 **고를 수만 있고 만들 수는 없었습니다**. 새로 등록한 고객의 관계도는 영원히 빈 상태였고, 관계 연결 폼의 두 선택 상자는 항상 비어 있었습니다.

### 고객 360의 담당자 패널

Customer 360에 **고객 담당자** 패널이 들어갔습니다. 등록·편집·삭제가 모두 이 자리에서 끝납니다.

한 줄에 담는 정보는 영업 담당자가 실제로 판단에 쓰는 것만 남겼습니다.

| 열 | 담는 것 |
| --- | --- |
| 신원 | 이름, 주 담당 여부, 부서 · 직책 |
| 역할 | 의사결정자 · 지지자 · 영향력자 · 실사용자 · 구매 담당 |
| 신호 | 영향력, 우리에 대한 성향(우호/중립/반대) |
| 접점 | 이메일, 연락처 |

성향은 색으로 구분합니다. 반대하는 사람이 목록에서 눈에 띄지 않으면 그 정보는 없는 것과 같습니다. 패널 머리글은 `3명 · 의사결정자 1명 · 지지자 1명`처럼 관계 구조를 한 줄로 요약합니다.

담당자가 없을 때는 빈 화면 대신 **왜 등록해야 하는지**와 등록 버튼을 함께 보여줍니다.

### 폼이 막다른 길이 되지 않게

담당자를 고르는 자리에는 **＋ 새 담당자**가 함께 있습니다.

- **의사결정 관계도**: 담당자가 2명 미만이면 연결 폼 대신 "담당자가 2명 이상 필요합니다"를 안내합니다. 고를 수 없는 선택 상자를 보여주는 것보다 낫습니다.
- **고객의 목소리 접수**: 고객을 고르면 그 고객의 담당자가 채워지고, 없으면 접수 화면을 떠나지 않고 바로 등록할 수 있습니다. 등록한 담당자는 자동으로 선택됩니다.

### 삭제가 기록을 지우지 않도록

담당자 삭제는 관계 연결을 함께 정리합니다. 떠난 사람을 가리키는 관계선은 의미가 없기 때문입니다. 반대로 **그 담당자로 접수된 고객 요청이 있으면 삭제를 거부**하고 몇 건인지 알려줍니다.

```
이 담당자로 접수된 고객 요청 1건이 있어 삭제할 수 없습니다.
요청의 담당자를 먼저 변경하세요
```

### `USER`가 두 가지를 뜻하던 문제

담당자 역할의 `USER`는 "실사용자"인데, 같은 코드가 Data Scope에서는 "본인"입니다. 하나의 번역 사전을 공유하다 보니 역할 선택 상자에 **본인**이 떠 있었습니다. 도메인별 해석을 분리했습니다.

## 2. 전략 고객 계획 — 띄어쓰기와 줄바꿈

### 보고된 문제

> 전략 고객 계획 부분에 두번째 textarea 부터 띄어쓰기나 엔터가 입력되지 않아서 변경이 어려운 상태야.

재현됩니다. `가 나` + Enter + `다` 를 입력하면 화면에는 `가나다` 가 남았습니다.

### 원인

목록형 항목(고객 목표, 전략 과제, 우리의 목표, 경쟁사, 위험 요인)은 배열을 줄바꿈으로 이어 붙여 보여주고, **입력할 때마다** 다시 배열로 쪼개고 있었습니다.

```
value={plan.customerGoals.join('\n')}
onChange={e => setPlan({ ...plan, customerGoals: lines(e.target.value) })}
// lines = 줄 단위로 trim 후 빈 줄 제거
```

키를 누를 때마다 `trim()`이 방금 친 공백을 지우고, 빈 줄 제거가 방금 누른 Enter를 지웠습니다. 저장 전에는 존재할 수 없는 중간 상태를 매 입력마다 강제한 셈입니다.

### 수정

목록형 칸은 브라우저가 값을 갖게 두고, **저장 시점에** 한 번만 줄 단위로 나눕니다. 계획 연도를 바꿔 다른 계획을 불러오면 폼이 새 기본값으로 다시 그려집니다. 저장 결과는 이전과 같습니다.

## 3. 고객 삭제 — 그리고 삭제하지 않아야 할 때

### 보고된 문제

> 등록한 고객은 어디서든 삭제 하는곳이 없는데.. 관리자는 삭제 가능해야 하지 않을까?

### 이력이 있으면 지우지 않습니다

고객 삭제는 참조를 먼저 셉니다. 영업기회 · 계약 · 견적 · 고객 요청 · 매출이 **하나라도 있으면 삭제하지 않고 비활성으로 전환**하고, 무엇 때문인지 알려줍니다.

```
영업기회, 계약, 견적, 고객 요청 이력이 있어 목록에서 숨김 처리했습니다.
기록은 그대로 보존됩니다.
```

아무것도 참조하지 않는 고객만 완전히 삭제하며, 이때 담당자 · 활동 · 작업 · 계획이 함께 정리됩니다. 전환된 Lead는 그 자체로 기록이므로 **삭제하지 않고 연결만 끊습니다**.

### 별도 권한

`customer:delete`를 신설했습니다. `customer:write`(등록·수정)와 분리한 이유는 단순합니다. 고객을 고칠 수 있는 것과 없앨 수 있는 것은 같은 권한이 아닙니다.

기본 Role(영업 담당자 · 영업 팀장)에는 **포함되지 않습니다**. 관리자는 `admin:*`로 이미 가능하며, 필요하면 `권한 · 데이터 범위` 화면에서 개별 Role에 부여할 수 있습니다.

확인 창은 **고객명을 직접 입력**해야 진행됩니다.

## 4. 리프레시하면 있던 화면에

### 보고된 문제

> 사용자/관리자 메뉴에서 리프레시하면 해당 메뉴에 그대로 있어야 할거 같은데, 메인 화면으로 이동하고 있어.

### 조사

12가지 경로(고객 목록, 고객 상세, 고객의 목소리, 관리자 화면 6종, 개인 화면, 질의문자열 포함 주소, 뒤로 가기)에서 **평범한 새로고침은 재현되지 않았습니다**. 주소는 그대로 유지됩니다.

재현되는 경로는 따로 있었습니다. **탭을 열어둔 채 세션이 만료된 뒤 새로고침**하면 `/login`으로 이동하고, 로그인에 성공하면 보고 있던 화면이 아니라 대시보드로 갑니다. 사용자 입장에서 이것은 "새로고침했더니 메인으로 갔다"와 구분되지 않습니다.

### 수정

로그인 화면으로 보낼 때 원래 화면을 기억하고, 로그인 후 그 자리로 돌려보냅니다. 비밀번호 변경을 마친 뒤에도 마찬가지입니다. 저장 대상은 `/app`, `/admin`, `/me` 경로로 제한하고 로그아웃 시 지웁니다.

## 발견 및 수정한 오류

- 담당자를 등록할 화면이 없어 의사결정 관계도가 새 고객에서 영원히 비어 있던 문제
- 담당자를 수정하거나 삭제할 방법이 없어 오타와 퇴사자가 관계도에 남던 문제
- 고객의 목소리 접수 화면에서 담당자를 매핑할 수 없던 문제
- 전략 고객 계획의 목록형 칸에서 띄어쓰기와 줄바꿈이 입력되지 않던 문제
- 고객을 삭제할 방법이 어디에도 없던 문제
- 세션 만료 후 로그인하면 보고 있던 화면 대신 대시보드로 이동하던 문제
- 담당자 역할 `USER`가 Data Scope의 "본인"으로 표시되던 번역 충돌
- 의사결정자가 역할과 표식 양쪽에 잡혀 같은 배지가 두 번 표시되던 문제
- 담당자 생성과 수정이 각자 검증 코드를 갖고 있어 서로 다른 값을 받아들일 수 있던 구조

## 검증 범위

- Go Test/Vet/`gofmt`, TypeScript Typecheck, React Production Build
- 담당자 입력 검증 단위 테스트: 기본값 적용, 대소문자 정규화, 알 수 없는 역할·영향력·성향 거부, 0~100 범위 밖 거부, 화면과 서버의 역할 목록 일치
- 실제 브라우저 검증 24항목 전수 통과
  - 담당자 등록 → 목록 반영 → 관계 폼 활성화 → 관계 선택지에 노출 → 편집 반영
  - 5개 목록형 칸 각각에 `가 나`+Enter+`다 라` 입력 후 값 일치, 저장 후 새로고침에도 유지
  - 6개 경로 새로고침 시 주소 유지, 세션 만료 후 로그인 시 원래 화면 복귀
  - 고객의 목소리 접수에서 담당자 선택 · 인라인 등록 · 접수 결과 반영
  - 요청이 걸린 담당자 삭제가 사유와 함께 거부됨
  - 이력 없는 고객은 완전 삭제, 이력 있는 고객은 비활성 전환
- 1440px · 900px 폭에서 가로 스크롤 0, 넘침 요소 0 확인

## 업그레이드

**마이그레이션이 없습니다.** 스키마는 010 그대로입니다.

`customer:delete`는 신설 권한이므로 기존 Role은 아무 영향을 받지 않습니다. 관리자(`admin:*`)는 즉시 사용할 수 있고, 특정 Role에 삭제를 허용하려면 `권한 · 데이터 범위` 화면에서 부여하십시오. 부여하지 않으면 고객 상세에 삭제 버튼이 나타나지 않습니다.
