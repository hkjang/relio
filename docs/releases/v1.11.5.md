## Relio v1.11.5 — MCP 권한을 실제 CRM 업무 도구로

v1.11.4에서 Qwen·OpenCode의 도구 목록 파싱과 개인 키 권한 변경을 복구했지만, 권한 화면의 `customer:write`는 실제 `tools/list`에 고객 등록 도구를 제공하지 않았습니다. 운영에서 보인 “38개 도구”는 키 Scope, 사용자 권한, 관리자 Tool 허용목록의 교집합이었고, 화면은 그 결과를 설명하지 못했습니다.

이번 릴리스는 권한 코드와 실제 MCP 도구를 전수 대조하고, 핵심 CRM 등록·수정 도구와 서버 기반 도구 카탈로그를 추가합니다.

## 1. 고객 등록·수정·삭제 MCP

다음 도구를 추가했습니다.

- `create_customer`: 고객명, 사업자번호, 산업군, 연락처, 등급, 매출 등으로 고객 등록
- `update_customer`: `version` 기반 낙관적 잠금과 부분 수정
- `delete_customer`: 이력이 없으면 삭제하고, 영업 이력이 있으면 기록 보존을 위해 비활성화

부분 수정은 보내지 않은 필드를 기존 값으로 유지합니다. 에이전트가 고객명만 수정했을 때 산업군, 이메일, 매출 같은 값을 0 또는 빈 값으로 덮어쓰지 않습니다.

## 2. 누락된 CRM Scope의 실제 도구 연결

권한 화면에는 있었지만 대응 도구가 없거나 부족했던 영역을 보완했습니다.

| CRM 영역 | 추가된 주요 MCP 도구 |
| --- | --- |
| 담당자 | 상세, 등록, 부분 수정, 삭제 |
| Lead | 목록, 등록 |
| 상품 | 목록, 등록 |
| 견적 | 목록 |
| 계약 | 상세, 등록, 활성화, 갱신 진행 수정, 매출 일정 |
| 매출 | 목록, 등록 |
| 영업목표 | 목록, 등록 |
| Forecast | 팀장 Override |
| 알림 | 목록, 읽음 처리 |
| 보고서 | Dashboard·Forecast·Win/Loss 종합 보고서 |

승인 정책이 비활성화된 기본 상태에서 77개, 활성화되면 승인 도구 4개를 포함해 최대 81개 도구를 제공합니다. 실제 노출 수는 계속해서 키 Scope, 사용자 권한, 관리자 Tool 허용목록의 교집합으로 제한됩니다.

## 3. 키 화면과 `tools/list`의 단일 계약

개인 연동 키 API가 서버의 실제 MCP 도구 카탈로그를 함께 반환합니다.

- 각 Scope에 현재 정책상 연결된 MCP 도구 수 표시
- 선택한 Scope 조합으로 실제 노출될 도구 수 계산
- MCP 도구가 0개인 조합은 저장 전에 경고
- 기존 키 목록에도 현재 정책 기준 MCP 도구 수 표시
- 관리자가 Tool 허용목록으로 새 도구를 제외한 경우도 화면에서 즉시 확인

도구에 여러 Scope가 필요한 경우 모든 Scope가 선택되어야 도구 수에 포함됩니다. 예를 들어 `create_customer`는 고객을 생성한 뒤 반환할 데이터의 접근 범위를 검증하므로 `customer:read`와 `customer:write`가 모두 필요합니다.

## 4. 호출 권한 재검증과 Scope 정합성

`tools/list`에 없는 도구 이름을 직접 `tools/call`로 보내도 실행되지 않도록 호출 시 동일 카탈로그를 다시 검사합니다. 관리자 Allowlist와 복합 Scope 조건이 도구 발견과 실행에 똑같이 적용됩니다.

기존 도구도 내부 CRM 서비스가 실제로 요구하는 복합 권한에 맞췄습니다. 고객 조회가 필요한 영업기회·견적·고객 요청 생성, 조회가 필요한 부분 수정, Forecast가 필요한 KPI 도구가 필요한 Scope를 정확히 선언합니다.

개인 키에 부여할 수 없었던 `voice:read`, `voice:write`, `forecast:write`도 허용 Scope에 추가했습니다. 사용자가 해당 Role 권한을 가진 경우에만 키로 위임할 수 있습니다.

## 검증 범위

- Go 전체 Test와 Vet, TypeScript Typecheck, React Production Build
- MCP 정의 81개와 실행 Handler 81개 일치 검사
- 모든 개인 키 CRM Scope의 실제 MCP 도구 연결 점검
- Qwen과 동일한 JSON-RPC 흐름: `initialize` → `tools/list` → `tools/call`
- MCP 고객 등록 → 이름만 부분 수정 → 기존 산업군·이메일 보존 → 삭제
- 키 권한 축소·복원, 관리자 Tool Allowlist 차단, 허용되지 않은 직접 호출 차단
- 완전 격리 Network 신규 설치 Smoke Test
- 컨테이너 교체 후 SSO Client Secret과 Personal Key 연속성 검증

## 업그레이드

DB Migration은 없습니다. 기존 개인 키의 Secret, Scope, Channel, 만료일은 그대로 유지됩니다.

관리자 화면에서 MCP Tool 허용목록을 비워 두었다면 새 도구가 사용자·키 권한에 따라 자동 노출됩니다. 허용목록을 명시적으로 사용 중이면 보안 정책상 새 도구가 자동 추가되지 않으므로, `create_customer` 등 허용할 새 도구를 목록에 추가해야 합니다. 개인 키 화면의 실제 도구 수로 적용 결과를 확인할 수 있습니다.
